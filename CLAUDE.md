## Overview

Rangiffler is a QA.GURU Advanced diploma template (README is in Russian): a photo-travel app with a GraphQL frontend. Students are expected to turn the monolithic `rfr-api` into microservices and add thorough test coverage. Gradle multi-project (`rfr`), Java 25, Gradle 9.7.1, Spring Boot 4.1.1.

| Module | Role | Port |
|---|---|---|
| `rfr-auth` | Spring Authorization Server (OAuth 2.0 / OIDC, Thymeleaf login/register pages) | 9001 |
| `rfr-api` | GraphQL backend, OAuth2 Resource Server (JWT, audience `rangiffler-api`) | 8081 |
| `rfr-gql-client` | React 19 + TS + Vite + Apollo frontend (npm project, not part of Gradle) | 3001 |
| `rfr-e2e` | JUnit 6 + Playwright Java + Allure tests (currently only a stub `SimpleTest`) | – |

## Commands

Infrastructure (MySQL 8.4 in Docker, root/`secret`; note `localenv.sh` stops and removes ALL Docker containers first):
```bash
bash localenv.sh
```
Run services (from repo root, each in its own terminal):
```bash
./gradlew :rfr-auth:bootRun
./gradlew :rfr-api:bootRun
cd rfr-gql-client && npm i && npm run dev
```
Build / test:
```bash
./gradlew build
./gradlew :rfr-api:generateJava      # regenerate GraphQL model classes
./gradlew :rfr-e2e:test              # all e2e tests
./gradlew :rfr-e2e:test --tests 'io.student.rangiffler.test.fake.SimpleTest'   # single test
cd rfr-gql-client && npm run lint && npm run build
```
`bash ports.sh` kills processes on 9001, 8081, 3001. GraphiQL: http://localhost:8081/graphiql.

## Architecture

- **Auth flow:** frontend logs in via `rfr-auth` (public client, access token — not id_token — is sent to the API). `rfr-api` validates JWTs against issuer `http://localhost:9001`; `@PreAuthorize` is on controllers (config in `RangifflerApiConfiguration`).
- **GraphQL schema is the contract:** `rfr-api/src/main/resources/graphql/query.graphqls`, written for the already-finished frontend. Java types (`io.student.rangiffler.model.types.*`) are generated by DGS Codegen (`generateJava`) into `build/generated` — never hand-write them. `UserConnection` / `PhotoConnection` are intentionally undefined in the schema; Spring for GraphQL auto-generates `*Connection` types (mapped to `Page<...>`; `Date` scalar → `LocalDate`). IDE red marks there are not errors.
- **Real vs mock in rfr-api:** users, friendships and countries use MySQL via JPA/Flyway (controller → `service/api` interface → `service/impl` → repository). Photos, likes, feed and stats are **mocks** (`FeedMockQueryController`, `PhotoMockMutationController`, `service/mock/FeedMockData` reading `resources/mock/*.json`) and persist nothing. Tables `photo`, `like`, `photo_like`, `statistic` already exist in `V1__schema_init.sql` but are unused; implementing them is the open work.
- **Database:** each service owns a MySQL schema (`rangiffler-api`, `rangiffler-auth`) with Flyway migrations under `src/main/resources/db/migration/<schema>/`. `V1__schema_init.sql` is written as a monolith schema meant to be split across future services. Profile rows are created lazily on first `Query.user` (default country `ru`).
- **Errors:** `GraphQlExceptionResolver` maps `ResourceNotFoundException` / `FriendshipActionException` to GraphQL errors (NOT_FOUND / BAD_REQUEST).
- Each module has its own README with more detail (`rfr-api/README.md` documents API behavior and structure).
