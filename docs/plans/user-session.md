# План: дополнительные браузерные сессии в UI-тестах (UserSession и GuestSession)

Статус: этап 1 закоммичен (`09677d3`), этап 2 написан и проверен пробами, не закоммичен.

## Цель

Дать тесту `rfr-e2e` второй `BrowserContext`, например для сценария «два пользователя одновременно» (один отправил приглашение, другой принял). Контекст создаётся как с авторизованным пользователем, так и без него. Жизненным циклом управляет JUnit, тест ничего не закрывает.

## Принятые решения

| № | Вопрос | Решение |
|---|---|---|
| 1 | Кто создаёт дополнительный контекст (правило 6) | `SessionExtension` берёт `Browser` у Playwright (`BrowserExtension.getOrCreateBrowser`), `SessionFixture` владеет контекстом. Основной контекст остаётся за `@UsePlaywright` |
| 2 | Вход через UI в расширении (правило 7) | Исключение: `SessionExtension` может вызвать `ui/flow/SignIn` (вход и ожидание главной страницы), больше ничего из `ui`. Замена на вход без UI (`storageState`) возможна позже и не затронет тесты |
| 3 | Главная страница | Тест строит её сам: `new MyTravelsPage(session.page())`. `data` не зависит от `ui` |
| 4 | Тип сессии | Два типа вместо `Optional`: `UserSession` (с пользователем) и `GuestSession` (без) |
| 5 | Трейс второго контекста | Отложено, решим позже |

## Этапы

### Этап 1. `UserExtension` создаёт пользователя на каждый `@User` (готово, `09677d3`)

- `beforeEach` создаёт по одному пользователю на каждый параметр `@User` в порядке параметров.
- Список фикстур лежит в Store под id теста. Фикстура регистрируется сразу после создания, поэтому падение на последующей закрывает предыдущие.
- Все `UserRequest` проверяются до создания первого пользователя.
- `afterEach` закрывает фикстуры в обратном порядке, первая ошибка сохраняется, остальные подавляются.
- Параметр находит свою фикстуру по позиции среди параметров `@User`.
- Правило 5 в `rfr-test-review` переписано.

### Этап 2. Сессии (написано, пробы проходят)

Типы и их место:

| Тип | Слой | Назначение |
|---|---|---|
| `UserSession(Page page, TestUser user)` | `data/` | record для теста: страница нового контекста, где вошёл `@User` пользователь |
| `GuestSession(Page page)` | `data/` | record для теста: страница нового контекста без входа |
| `SessionFixture` | `data/fixture/` | владелец контекста и страницы, `AutoCloseable`, тесту не передаётся |
| `SessionExtension` | `jupiter/extension/` | `ParameterResolver` и `AfterEachCallback` |

Поведение `SessionExtension`:

1. Поддерживает только параметры типов `UserSession` и `GuestSession` (правило 11).
2. Для параметра вне тестового метода, `UserSession` без `@User` и `GuestSession` с `@User` падает с `ParameterResolutionException`.
3. Создаёт контекст из `Browser` Playwright с `PlaywrightOptions.contextOptions()` и таймаутами `TestConfig`.
4. Регистрирует `SessionFixture` в Store до входа, чтобы падение входа не оставило контекст открытым (правило 2).
5. Для `UserSession` берёт пользователя `UserExtension.fixture(...)` по позиции параметра, входит через `new SignIn().signIn(page, username, password)` (`ui/flow`), который сам ждёт главную страницу.
6. `afterEach` закрывает контексты в обратном порядке, первая ошибка сохраняется. Выполняется раньше очистки `UserExtension`, потому что расширение зарегистрировано в `BaseWebTest` после него: браузер закрывается до удаления пользователя.

Изменения в существующем коде:
- `UserExtension`: `NAMESPACE` и метод `fixture(ParameterContext, ExtensionContext)` доступны внутри пакета.
- `PlaywrightOptions.contextOptions()` доступен внутри пакета.
- `BaseWebTest`: `@ExtendWith({UserExtension.class, SessionExtension.class})`.
- Правила 6 и 7 в `rfr-test-review` получили исключения для `SessionExtension`.

Пример использования в тесте:

```java
@Test
void shouldAcceptInvitation(@User TestUser sender, @User UserSession receiver) {
    ...
}
```

## Пробы

`jupiter/probe/SessionExtensionTest` (тег `ui`, нужен запущенный стенд; каждый образец запускается в новом потоке, потому что Playwright держит свой экземпляр в `ThreadLocal` и закрывает его после прогона EngineTestKit; на внешнем классе стоит `@UsePlaywright`, потому что Playwright ищет аннотацию на самом внешнем классе):

1. Гость: отдельный контекст, пустая страница, закрыт после теста.
2. Пользователь: залогинен на своей странице, основная страница не тронута, пользователь удалён, контекст закрыт.
3. `UserSession` без `@User` падает с ожидаемым сообщением.
4. `GuestSession` с `@User` падает с ожидаемым сообщением, созданный пользователь удалён.
5. Падение входа (пользователь удалён до входа): тест падает с `AssertionFailedError`, контекст сессии закрыт, пользователь удалён.
6. `@User TestUser` и два `@User UserSession`: три разных пользователя, обе сессии вошли, контексты закрыты, все пользователи удалены.

Запуск:

```bash
./gradlew :rfr-e2e:e2e --tests '*SessionExtensionTest' --tests '*UserExtensionTest'
```

## Риски

- Параллельный запуск тестов: `Browser` берётся из потока теста, контексты закрываются тем же потоком. Параллельный запуск пока не проверялся.
- Вход через UI медленнее и зависит от страницы приветствия: её изменение ломает расширение, а не только тесты входа.
- `UserSession` и `GuestSession` держат `Page`, который принадлежит `SessionFixture`. Тест не должен закрывать его сам.
